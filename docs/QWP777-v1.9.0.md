# QWP-777 v1.9.0

## Release scope
- Unified release audit CLI: `src/qwp777_release_audit.py`.
- Combines unit tests, API compatibility, regression on the historical v1.5.0 baseline, regression on the current v1.9.0 baseline, checksum verification, cross-release report comparison, and signature self-tests.
- Optional verification of a supplied HMAC- or Ed25519-signed archive.
- Full generated report included at `docs/RELEASE_AUDIT.json`.
- API version 1.9; experiment schema remains `qwp777-experiment-1`.

## Full release audit
```bash
python src/qwp777_release_audit.py -o docs/RELEASE_AUDIT.json
```
The command runs the unit suite, then executes API compatibility and both regression baseline checks. It compares the current regression report with the frozen v1.8.0 regression report. HMAC-SHA256 verification is tested using a temporary secret; Ed25519 signing and public-key verification are self-tested if `cryptography` is installed. Temporary keys and secrets are not written into the package.

A nonzero exit code indicates a failed required check. The JSON report records each check, detailed results, and caveats.

## Verify an existing signed artifact as part of the audit
Ed25519:
```bash
python src/qwp777_release_audit.py --verify-archive reports/archive/ARCHIVE_NAME.zip --public-key "$HOME/.config/qwp777/qwp777-public.pem" -o release-audit.json
```
HMAC:
```bash
export QWP777_ARCHIVE_HMAC_KEY='your-shared-secret'
python src/qwp777_release_audit.py --verify-archive reports/archive/ARCHIVE_NAME.zip -o release-audit.json
```
When an external archive is supplied, the audit requires verification to succeed. HMAC is symmetric and needs the same secret; Ed25519 verifiers need only the trusted public key.

## Regression report comparisons
The release comparator supports report schema v1 and v2:
```bash
python src/qwp777_release_compare.py previous-regression.json current-regression.json -o release-diff.json
```
The v1.8.0 comparison fixture is `compatibility/reports/v1.8.0-regression.json`. Its six known cases are compared against the current run using the preserved v1.5.0 baseline.

## Baselines and checksums
- `regression/baselines/v1.5.0.json` is retained as the historical gate.
- `regression/baselines/v1.9.0.json` is a separate current-version snapshot.
- `regression/baselines/v1.9.0.json.sha256` verifies the exact baseline bytes.
- Baseline refreshes require explicit `--approve` and refuse to overwrite existing files.

## Limits
The release audit is a finite regression and integration report, not formal verification. A clean result means only that the specified checks passed. Ed25519 self-test validates the implementation path with ephemeral keys, not trust in a third party's public key. Qiskit Aer remains optional and is not claimed to have been run if the audit reports it unavailable. QWP-777 is not physical quantum hardware and is not a universal arbitrary-circuit simulator for 777 qubits.
