# QWP-777 v1.7.0

## Release scope
- **Versioned regression baseline refresh:** `qwp777_baseline.py` captures new fixed-seed outcomes from an existing baseline into a new versioned JSON file, only after `--approve`. Existing baselines are never overwritten. A `.sha256` checksum accompanies each new baseline.
- **Manifest authentication:** report archives can optionally carry an HMAC-SHA256 signature. `qwp777_verify_archive.py` verifies the HMAC and checks the archived report/configuration hashes.
- **API compatibility:** `qwp777_api_compat.py` checks current public exports and callable signatures against `compatibility/api-v1.6.0.json`.
- Result schema stays `qwp777-experiment-1`; API version moves to 1.7.

## API compatibility check
```bash
python src/qwp777_api_compat.py -o api-compatibility-report.json
```
Expected result is `compatible: true` when legacy symbols, stored function signatures, and result schema remain compatible. The check is source-level, not an exhaustive behavioral proof.

## Versioned baseline refresh
```bash
python src/qwp777_baseline.py --baseline-version 1.7.0 --approve --report baseline-refresh-report.json
python src/qwp777_regression.py --baseline regression/baselines/v1.7.0.json -o regression-report.json
```
The original v1.5.0 file remains in place. `--approve` is required; destination collisions fail instead of replacing a prior baseline. Inspect the generated counts and verify the `.sha256` file before using the baseline as a release gate.

## Signed report archive
Set the shared secret in an environment variable outside the repository. Example for Termux/Linux:
```bash
export QWP777_ARCHIVE_HMAC_KEY="$(python -c 'import secrets; print(secrets.token_hex(32))')"
python src/qwp777_archive.py backend-comparison.json --config examples/bell.json --archive-dir reports/archive --require-signature
python src/qwp777_verify_archive.py reports/archive/ARCHIVE_NAME.zip
```
The second command verifies the archive created by the first; substitute its actual output path. The verifier reads the same environment variable by default. Signing is HMAC-SHA256 symmetric authentication, not an Ed25519/RSA public-key signature. Anyone who verifies must possess the secret, so distribute it through a secure separate channel. The key is never written into the report archive.

## Optional external backend comparison
```bash
python src/qwp777_backend_compare.py examples/bell.json -o backend-comparison.json
```
This uses Qiskit Aer only if both dependencies are installed. Otherwise, it writes `optional_backend_unavailable` in the JSON report.

## Known limits
Baseline changes may be legitimate but require review. Exact-count regression is sensitive to RNG or implementation changes. API checks do not prove identical side effects or semantics. HMAC protects archive authenticity only for holders of the shared secret; it does not establish scientific correctness. QWP-777 remains a software prototype, not physical quantum hardware, and does not claim universal simulation of arbitrary 777-qubit circuits.
