# QWP-777 v1.8.0

## Release additions
1. Enhanced regression reports: baseline file SHA-256, per-outcome count deltas, probability deltas, TVD, Hellinger distance, and aggregate summary.
2. Cross-release report comparison: `src/qwp777_release_compare.py` accepts regression-report schema v1 and v2, and reports case additions/removals, failures that appear/disappear, and distribution changes.
3. Ed25519 public-key signatures for report archives using the optional `cryptography` package. Existing HMAC-SHA256 signatures remain supported.
4. Public-key verification CLI and key-pair generation CLI.
5. New separately versioned v1.8.0 baseline and checksum; the historical v1.5.0 baseline remains preserved.

## Compare reports from releases
Create report files with the matching release version:
```bash
python src/qwp777_regression.py -o old-regression.json
python src/qwp777_release_compare.py old-regression.json new-regression.json -o release-diff.json
```
The comparison handles regression report schemas `qwp777-regression-report-1` and `qwp777-regression-report-2`. A `regression_failure` means a case passed in the older report but failed in the newer one. `counts_changed_but_passed` reports changed empirical outcomes even when the current case's baseline test passed.

## Ed25519 keys
```bash
export QWP777_ED25519_PASSPHRASE='choose-a-strong-passphrase'
python src/qwp777_ed25519_keys.py --private-key "$HOME/.config/qwp777/qwp777-private.pem" --public-key "$HOME/.config/qwp777/qwp777-public.pem" --passphrase-env QWP777_ED25519_PASSPHRASE
```
Private keys are encrypted when a passphrase environment variable is specified, are written with restricted file permissions where supported, and are never included in report archives. Key generation refuses to overwrite existing key files.

## Create and verify an Ed25519-signed archive
```bash
python src/qwp777_archive.py backend-comparison.json --config examples/bell.json --archive-dir reports/archive --ed25519-private-key "$HOME/.config/qwp777/qwp777-private.pem" --private-key-password-env QWP777_ED25519_PASSPHRASE --require-signature
python src/qwp777_verify_archive.py reports/archive/ARCHIVE_NAME.zip --public-key "$HOME/.config/qwp777/qwp777-public.pem"
```
Use the actual ZIP path printed by the archiver. The manifest stores an Ed25519 signature and SHA-256 fingerprint (`key_id`) for the public key. Verification checks the signature, key ID, archive CRC, file hashes, and file sizes. The verifier does not need the private key or passphrase.

Ed25519 is asymmetric signing. HMAC-SHA256 remains available but is symmetric and requires the same secret on signer and verifier. `cryptography` is an optional dependency and errors clearly if not installed.

## Baselines
`regression/baselines/v1.5.0.json` remains the default regression gate. `regression/baselines/v1.8.0.json` is a separate baseline snapshot with a `.sha256` sidecar. A baseline refresh is a deliberate versioned action and must be reviewed before it becomes an authoritative release gate.

## Limitations
Regression reports reflect a finite set of sampled circuits. Distribution changes can arise from intended changes, random sampling, or implementation changes; investigate rather than treating every difference as a defect. Cryptographic signatures authenticate artifact bytes for the selected key trust model but do not establish scientific validity. QWP-777 is a software prototype, not physical quantum hardware or a universal 777-qubit arbitrary-circuit simulator.
