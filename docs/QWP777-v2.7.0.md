# QWP-777 v2.7.0 — Release Notes

## Scope

QWP-777 v2.7.0 adds deterministic release packaging and file-level integrity verification. It does not alter the public simulator API or experiment result schema.

## New tool: `src/qwp777_release_package.py`

Commands:

- `manifest`: create `docs/RELEASE_MANIFEST.json`.
- `verify`: compare all manifested paths, sizes, and SHA-256 hashes with files in the source tree.
- `build`: create a fresh manifest, verify it, build a ZIP outside the source tree, run ZIP CRC validation, and write a detached `.sha256` sidecar.
- `verify-archive`: compare the archive against its sidecar and run a ZIP CRC check.

The manifest lists every regular project file except itself and excludes `.git`, `__pycache__`, and `.pyc` build artifacts. Paths must be relative, unique, and traversal-free. Symbolic links are not permitted. The manifest intentionally cannot hash itself; the ZIP is hashed separately by its sidecar.

SHA-256 provides integrity checking, not publisher authentication. Use the existing signed archive flow and a trusted public key when authentication is required.

## Compatibility

- API version: `2.7`.
- Result schema remains `qwp777-experiment-1`.
- Public `qwp777_api` exports and callable signatures remain unchanged.
- v2.7.0 baseline is derived from the exact fixed-seed counts in v2.6.0, without changing expected outputs to fit the current implementation.

## Validation

The release audit includes a release-manifest smoke check. Passing unit tests and finite regression cases are not formal verification and do not prove correct simulation of arbitrary circuits or physical hardware equivalence.
